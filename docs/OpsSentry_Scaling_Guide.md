# OpsSentry 分布式集群扩容指南 (v1.0)

## 1. 扩容策略 (Scaling Strategy)
OpsSentry 支持 **水平横向扩容 (Scale-Out)**。由于采用了无状态的分布式设计，增加节点只需简单启动新的 Agent 容器并指向相同的 Redis 协调器与中心 API。

## 2. 扩容步骤 (Expansion Steps)

### 步骤 1：节点准备
- 操作系统：Linux (x64) / Windows (x64)。
- 环境依赖：Docker 20.10+ 或 Python 3.9+。
- 网络准入：确保新节点可访问中心 API (Port 8000) 与 Redis (Port 6379)。

### 步骤 2：密钥与配置分发
1. 从 `ConfigShield` 获取集群共享密钥 (`CLUSTER_SECRET`)。
2. 配置环境变量：
   ```bash
   export AGENT_ID="node-$(hostname)"
   export REDIS_HOST="cluster-redis-internal"
   export CLUSTER_SECRET="your-hmac-key"
   export API_ENDPOINT="https://opssentry-hub:8000"
   ```

### 3. 部署加固 (Mandatory Hardening)
为符合 Phase 10 生产级加固要求，所有新节点必须遵循以下规范：
- **非特权运行**: Docker 镜像内部必须使用非 root 用户（如 `opssentry` 用户）。
- **资源限制**: 在 `docker-compose` 或 `k8s` 中限制单节点：
  - CPU Limit: `0.5 - 1.0 Core`
  - Memory Limit: `512MB - 1GB`
- **只读文件系统**: 挂载代码目录为 `:ro` 模式。

### 步骤 3：节点注册与热启动
启动容器后，节点将执行 `ACTIVE_INIT` 流程：
1. 向 Redis 注册心跳租约（Lease）。
2. 发送首个 HMAC 签名的心跳包。
3. HUD 2.0 热力图中将自动出现新的节点格子，并呈绿色脉动。

## 3. 性能上限预警
- **Redis 瓶颈**: 当节点规模超过 **2000+** 时，建议将单机 Redis 升级为 Redis Cluster 模式。
- **审计聚合瓶颈**: 若单秒审计流水超过 **10,000 条**，应开启 `AuditShipper` 的批量压缩上传模式。

## 4. 扩容后校验
- 执行 `tests/test_cluster_scaling.py` 验证新节点的任务接管率。
- 在 HUD 上观察 `Stress Pulse` 是否随节点增加而从红色/琥珀色平滑转为绿色。
