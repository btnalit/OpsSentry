## 1. 项目愿景
OpsSentry 是一个分布式的、具备自主决策与执行能力的运维 Agent 系统。它旨在将 Accio 架构中"本地可靠性"的优势（如任务持久化、资源锁控）引入企业级 IT 运维场景，实现"端侧自治、全局同步"的智能运维。

## 2. 核心功能需求

### 2.1 端侧自治能力 (Edge Autonomy)
- **可靠指令流**：即使在极端断网或重启后，Agent 必须能够恢复并继续执行之前的运维任务。
- **并发冲突防护**：在多 Agent 环境中，必须防止对同一个配置文件（如 Nginx, SSHD）的并发冲突修改。
- **本地感知与自愈**：Agent 需能独立在本地进行日志巡检、故障诊断并执行预设的修复脚本。
- **离线知识支持**：在断网环境下，Agent 需能利用本地存储的排障手册进行决策支持。

### 2.2 全局同步能力 (Global Sync)
- **状态同步总线**：端侧 Agent 的任务进度通过 **OpsLedger 独立账本**（`data/ops-queue/ledger.jsonl`）持久化，并加密同步至中控台。
  > ⚠️ **注意**：同步账本为 OpsLedger 专用路径，**不使用** Accio 框架的 `.accio/agents/msg-queue/task.jsonl`，二者物理隔离，防止"加载即删除"语义干扰断点续传。
- **审计日志闭环**：所有 Agent 的思考过程 (Thought) 和动作 (Action) 需全量上报。
- **集中策略分发**：安全策略 (Policy) 与新技能 (Skills) 需支持从中控台热推送到所有哨兵节点。

## 3. 用户角色与权限
- **超级管理员 (VICTOR)**：负责全局策略审核、高风险操作最终审批。
- **运维哨兵 (Sentry Node)**：在生产节点上执行具体的观测、诊断与执行任务。

## 4. 关键技术指标
- **状态恢复耗时**：节点重启后，恢复未完成任务的状态耗时 < 5s。
- **锁粒度**：
  - Phase 1：文件级、目录级本地锁，TTL 默认 30s，心跳续期间隔 10s。
  - Phase 2：扩展为基于 CMDB 标签的跨节点逻辑锁。
- **知识检索延迟**：本地 BM25 检索 10GB 以内的知识库（`data/knowledge/`），首词延迟 < 100ms。
- **离线降级**：中控台不可达时，端侧所有核心功能（OpsLedger / ConfigShield / KnowledgeCore）必须保持可用，网络恢复后自动重放缓冲队列。
